# 自己管理ポータル 仕様書

作成日: 2026年11月11日
目的: 自分1人で使う自己管理用Webアプリ。PCとスマホから同じデータを使い、ポータル（ホーム画面）から各機能に移動できる形にする。

---

## 0. 実装の進め方（Claude Code向け）

- 実装は「8. 実装フェーズ」の順に1フェーズずつ行う。各フェーズの終わりで動作確認できる状態にする
- 仕様に書かれていないこと・矛盾していることは、推測で決めずに質問する
- 「10. 未決事項」に挙げたものは、該当フェーズに入る前に確認する
- 画面の文言はすべて日本語

---

## 1. 前提

- 利用者: 自分1人
- 端末: PC（ブラウザ）とスマホ（ブラウザ／ホーム画面に追加したPWA）。どちらからでも同じデータを読み書きできる
- タイムゾーン: Asia/Tokyo。日付の区切りはすべて日本時間
- 金額: 円、整数で扱う
- 費用: 各サービスの無料プランの範囲で運用する

---

## 2. 技術構成

| 項目 | 採用するもの |
|---|---|
| 画面・サーバー | Next.js（App Router）+ TypeScript |
| スタイル | Tailwind CSS |
| データベース・ログイン | Supabase（PostgreSQL、Auth） |
| 公開先 | Vercel（GitHub連携で自動デプロイ） |
| スマホ対応 | PWA（ホーム画面に追加できる。オフライン対応は不要） |
| グラフ | Recharts など、Reactで使える軽量なもの |
| カレンダー読み込み | iCalを解析できるライブラリ（繰り返し予定の展開に対応しているもの） |

### ログインとデータ保護

- Supabase Authのメールログイン（マジックリンク）を使う
- 自分のアカウントを作ったら、Supabase側で新規登録を無効にする。加えて、環境変数 `ALLOWED_EMAIL` 以外のユーザーはアプリ側でも弾く
- すべてのテーブルに `user_id` を持たせ、Row Level Security で本人のデータだけ読み書きできるようにする

### 環境変数

- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `ALLOWED_EMAIL`
- `GOOGLE_CALENDAR_ICAL_URL`（Googleカレンダーの非公開URL。サーバー側だけで使い、ブラウザには絶対に渡さない）

`.env.local` はGitに含めない。

## 3. 画面構成

```
ホーム（ダッシュボード）            /
├─ タスク                           /tasks
├─ メモ                             /notes
├─ 勤怠                             /attendance
├─ 勉強・練習スケジュール           /study, /study/[id]
├─ お金                             /money
│   ├─ 記録一覧                     /money/transactions
│   ├─ 貸し（まとめ払いの回収）     /money/loans
│   ├─ クレカ照合                   /money/cards
│   ├─ 月次チェック                 /money/check
│   └─ 推移・レポート               /money/reports
├─ 謎解きメモ                       /nazo
├─ IELTS                            /ielts
└─ 設定                             /settings
```

- PC: 左のサイドメニューから全機能に移動
- スマホ: 画面下部に「ホーム / タスク / 勤怠 / お金 / メニュー」。メニューから残りの機能に移動
- 予定（Googleカレンダー）は専用ページを作らず、ホームのカードのみ

---

## 4. ホーム画面

カードの並びは以下で固定（並び替え・表示切替は作らない）。PCは格子状、スマホは縦1列。

1. **日付と勤怠ボタン**: 今日の日付。勤怠の「開始」「終了」ボタン。記録中なら種類と経過時間を表示
2. **予定**: Googleカレンダーの今日〜3日後の予定（終日予定を含む）
3. **タスク**: 期限切れと今日が期限のタスク。チェックで完了にできる
4. **勉強・練習**: 今日の勉強時間、連続記録日数、各試験までの残り日数、今日の計画（今日の目標ページ）、次のバンド練習までの日数
5. **お金**: 今月の収入・支出・差額、未回収の貸しの合計、次のクレカ支払日と照合状況
6. **IELTS**: 4技能の直近スコアとオーバーオールの目安

各カードから該当機能のページに移動できる。

## 5. 各機能の仕様

### 5.1 タスク

**タスクの項目**

- タイトル（必須）
- 本文
- カテゴリ（1つ。自分で追加・名前変更・削除・色設定ができる）
- 期限（任意。日付のみ、時刻は持たない）
- 状態: 未完了 / 完了
- サブタスク: チェックリスト形式。1段階のみ。親タスクに「2/5」のように進み具合を表示
- 作業ログ: 日時付きのメモを好きなときに追加していく。新しいものが上。後から編集・削除できる
- 機能リンク（任意）: アプリ内の特定ページへのリンク（例: 月次チェック画面）

**定期タスク**

- 繰り返し方: 毎日 / 毎週（曜日を複数選択可）/ 毎月（日にち指定。31日など存在しない日は月末扱い）/ ◯日ごと
- 1つの繰り返し設定につき、未完了のタスクは常に1つだけ。期限が過ぎても次の回は作らない（サボっても溜まらない）
- 完了したときに次の回を作る。次の期限は「繰り返しのルールに合う日のうち、前回の期限と完了日のどちらよりも後で、最も早い日」
- 繰り返し設定の編集・停止ができる

**機能との連携**

- 機能リンクに「月次チェック」を設定したタスクは、月次チェック（5.3）を完了した時点で自動的に完了にする
- 想定する定期タスクの例: 所持金チェック（毎月）、部屋の掃除

**一覧画面**

- 「期限切れ」「今日」「今後」「期限なし」に分けて表示
- カテゴリで絞り込み
- 完了済みは別タブで確認できる

### 5.2 メモ（Google Keep風）

- カードをタイル状に詰めて並べる表示（高さの違うカードが隙間なく並ぶ形）
- 画面上部の入力欄からすぐ書ける。タイトルは任意
- 種類: テキストメモ / チェックリストメモ（項目ごとにチェック、チェック済みは下に移動）
- タグ: 1つのメモに複数。サイドメニュー（スマホはメニュー内）からタグで絞り込み。タグの追加・名前変更・削除ができる
- 背景色: カードごとに数色から選べる
- ピン留め: 一覧の上部に固定
- アーカイブ: 一覧からは隠すが残す。アーカイブ一覧から戻せる
- ゴミ箱: 削除したメモは7日間残り、その後自動で完全削除。ゴミ箱から戻せる
- 検索: タイトル・本文・タグを横断
- 画像の添付はなし

メモのタグと謎解きメモのタグは別管理にする。

### 5.3 お金（貯金管理）

自分の収入・支出の推移を確認するための機能。入力はすべて手動。

#### お金の置き場所

| 置き場所 | 種類 | 扱い |
|---|---|---|
| 通常口座 | 口座 | 残高を持つ |
| 貯金口座 | 口座 | 残高を持つ |
| 現金 | 現金 | 残高を持つ |
| PayPay | 電子マネー | 残高を持つ |
| クレカA | クレジットカード | 未払い額（借り）を持つ |
| クレカB | クレジットカード | 未払い額（借り）を持つ |

- 設定画面で名前の変更・初期残高の設定ができる
- Suicaは置き場所として持たない（下記「Suicaの扱い」参照）

#### 記録の種類

- **支出**: 日付、金額、支払った置き場所、カテゴリ、メモ
- **収入**: 日付、金額、入った置き場所、カテゴリ、メモ
- **振替**: 日付、金額、移動元、移動先、メモ。通常口座→貯金口座、PayPayへのチャージ、クレカの引き落としなど。支出・収入には数えない
- **調整**: 月次チェックで原因不明の差額が出たときに残高を合わせるための記録。レポートでは支出・収入と分けて表示する

支出カテゴリの初期値: 食費、日用品、交通費、交際費、趣味、勉強、住居、通信、医療、その他
収入カテゴリの初期値: 給与、その他
（カテゴリは設定画面で追加・編集できる）

#### Suicaの扱い

- 「Suicaチャージ」ボタンから、チャージ元の置き場所（現金・クレカなど）と金額を入力すると、カテゴリ「交通費」の支出として記録される
- Suicaの残高は管理しない（月次チェックの対象外）

#### まとめ払い（貸し）

- 支出の入力時に「まとめ払い」をオンにすると、次を入力する
  - 支払った全額
  - 自分の負担分
  - 貸した相手と金額（複数人。相手の名前は過去の入力から候補を出す）
- 自分の負担分＋貸しの合計＝全額 になっていなければ保存できない
- 置き場所からは全額が出ていく。支出として集計されるのは自分の負担分だけ
- 貸し一覧: 相手ごと・案件ごとに未回収の金額を表示
- 回収時: 回収日と方法（PayPay / 振込 / 現金）を選ぶ。PayPay→PayPay、振込→通常口座、現金→現金 にそれぞれ入金される。回収は収入には数えない

#### クレカ照合

- カードごとに設定: 締め日（末日も可）、支払日、支払月（締めの翌月 / 翌々月）、引き落とし口座
- 締め期間ごとに、そのカードで支払った記録（まとめ払いは全額）を合計して「アプリ上の請求額」を表示
- 支払日の前後に、明細の実際の請求額を入力する
  - 一致: 「一致」として記録
  - 不一致: 差額を表示し、その締め期間の利用一覧を表示して確認できるようにする
- 照合が済んだら、引き落とし口座→カードの振替（実際の請求額）をワンタップで記録できる
- ホームには次の支払日と、照合済み／未照合を表示

#### 月次チェック（残高の突き合わせ）

- 月に1回、各置き場所（通常口座、貯金口座、現金、PayPay）の実際の残高を入力する。クレカは支払日の照合で確認するため対象外
- アプリ上の残高と比べて差額を表示
- 差額がある場合: 記録漏れを追加するか、「調整」として記録して残高を合わせる
- チェックの結果（日付、置き場所ごとのアプリ残高・実際の残高・差額）は履歴として残す
- 完了すると、機能リンク「月次チェック」の付いた未完了タスクを自動で完了にする（5.1）

#### 推移・レポート

- 月ごとの収入・支出・差額の棒グラフ
- 月ごとのカテゴリ別支出の内訳
- 貯金口座の残高推移、全置き場所の合計（資産−クレカ未払い）の推移

### 5.4 予定（Googleカレンダー連携・読み取りのみ）

- `GOOGLE_CALENDAR_ICAL_URL` のiCalをサーバー側で取得・解析する
- 繰り返し予定も展開して表示する。時刻はAsia/Tokyoで表示
- 取得結果は15分程度キャッシュする
- 予定の追加・編集はGoogleカレンダー側で行う（アプリからは書き込まない）
- 取得に失敗したらカード内に「予定を読み込めませんでした」と表示し、他のカードには影響させない

### 5.5 勤怠

勉強に限らず使える汎用の時間記録。「自分が頑張った」と実感できる表示を重視する。

**記録**

- 種類: 自分で追加・編集できる。初期値は「勉強」「ドラム」「仕事」
- 「開始」「終了」ボタンで記録。記録中の状態はデータベースに持ち、PCで開始してスマホで終了、もできるようにする
- 同時に記録できるのは1件だけ
- 押し忘れに備えて、手動での追加・開始終了時刻の修正・削除ができる
- 日をまたいだ記録は開始日の分として集計する
- 種類が「勉強」のとき: 取り組み・科目・教材を選ぶ（教材は任意）。終了時に「何ページまで進んだか」を入力でき、勉強スケジュールの進捗に反映される
- 種類が「ドラム」のとき: 曲を選べる（任意）
- メモ欄

**頑張りの見える化**

- 連続記録日数（ストリーク）: 全体と種類ごと
- カレンダー型のヒートマップ: 記録時間が長い日ほど色が濃い
- 今週・今月の合計時間と、先週・先月との比較
- 種類別・取り組み別・科目別の累計時間と、日・週・月ごとのグラフ

### 5.6 勉強・練習スケジュール

一番上の階層を「取り組み」とし、試験タイプと練習タイプの2種類を扱う。

```
取り組み
├─ 試験タイプ: 謎検 / IELTS / 中小企業診断士
│   ├─ 試験日
│   └─ 科目 → 教材 → 計画
└─ 練習タイプ: ドラム
    ├─ 曲目 → 練習ログ
    └─ バンド練習日
```

#### 試験タイプ

- 取り組み: 名前、試験日（残り日数を表示）、メモ
- 科目: 取り組みごとに自由に追加。科目分けが不要なら「全般」1つでよい
- 教材: 科目ごと。教材名、総ページ数
- 計画: 科目、教材、内容（例: 第3章）、開始ページ、終了ページ、開始日、終了日
  - 期間とページ数から「1日あたり約◯ページ」を自動計算して表示
  - 今日時点で到達しているべきページ（期間内で均等に進める前提）と、実績のページを比べて「予定どおり / 遅れ / 先行」を表示
  - 実績のページは、勤怠の終了時の入力、または計画画面での手入力で更新する
- 「今日の計画」: 今日が期間に含まれる計画と、今日の目標ページを一覧表示（ホームにも表示）

**計画の登録方法**

- 手動: 画面から1件ずつ追加・編集・削除
- CSV取り込み: 1行＝1つの計画
  ```
  試験,科目,教材,内容,開始ページ,終了ページ,開始日,終了日
  中小企業診断士,財務・会計,〇〇テキスト,第3章,45,80,2026-11-15,2026-11-20
  ```
  - 文字コードはUTF-8（BOM付きでも読めるように。Excelで保存したファイルを想定）
  - 取り込む前にプレビューを表示し、行ごとにチェック結果を出す
    - 日付の形式が不正、開始日＞終了日、開始ページ＞終了ページ → エラー
    - 未登録の取り組み → エラー
    - 未登録の科目・教材 → 「新規作成されます」と表示し、確認後に作成
  - エラーのある行を除いて取り込むか、全体を中止するかを選べる
- CSV書き出し: 現在の計画を同じ形式で出力する（スプレッドシートで編集して再取り込みできる）

#### 練習タイプ（ドラム）

- 曲目: 曲名、アーティスト、メモ（参考音源のリンクなど）
- 練習ログ: 曲ごとに日時付きのメモを積み上げる（タスクの作業ログと同じ形式）。進捗はログに自由に書く（段階やBPMなどの専用項目は持たない）
- バンド練習日: 日付、場所・メモ、その日にやる曲（複数）。次のバンド練習までの日数と、その日にやる曲をホームと取り組み画面に表示

#### 初期データ

- 謎検（試験）
- IELTS（試験、General Training、試験日 2026-12-11）。科目は Listening / Reading / Writing / Speaking
- 中小企業診断士（試験）
- ドラム（練習）

### 5.7 謎解きメモ

1ページを3つのタブに分ける。

**① 小謎アイデア**

- タイトル、本文
- 答え・解説（任意）。答えは普段は隠し、タップで表示
- タグ（複数。種類分け用。謎解きメモ専用のタグ）
- タグでの絞り込み、検索

**② 公演の経験履歴**（伏線のある中〜大謎）

- 公演名、主催・団体名、参加日
- 公演ページのリンク（複数）
- 感想
- 任意項目: 結果（成功 / 失敗）、評価（★1〜5）、形式（ルーム型 / ホール型 / 周遊型 / オンライン / その他）、一緒に行った人
- 参加日順の一覧、検索

**③ ギミックアイデア**

- タイトル、メモのみ

### 5.8 IELTS

4技能の練習記録を貯めて、バンドスコアの推移を見るページ。受験区分は **General Training**。勉強スケジュールの取り組み「IELTS」と紐づく（このページにはIELTSの計画と勤怠の集計も表示する）。

#### 共通の記録項目

- 日付、技能、使った練習ページ・教材、バンドスコア、かかった時間（分）、所感

かかった時間を入力した記録は、勤怠に「勉強 / IELTS / 該当技能」として自動で記録する（記録画面でオフにもできる）。

#### Reading / Listening

- 難易度（Claudeによる判定）、正答数、問題数
- 正答数からバンドスコアの目安を自動計算する。換算表は技能ごとに設定ファイルで持ち、ReadingはGeneral Training用を使う（値は「10. 未決事項」参照）

#### Writing

- Task 1 / Task 2 の区別、お題、自分の解答文
- 採点結果: 総合バンドと4観点（Task Achievement（Task 1）または Task Response（Task 2）、Coherence and Cohesion、Lexical Resource、Grammatical Range and Accuracy）
- フィードバック（チャットで受け取った文をそのまま保存）

#### Claudeの結果の取り込み（R / L / W）

- 技能ごとに「Claude用の指示文をコピー」ボタンを置く。指示文は、問題や解答と一緒にClaudeへ貼ると、次の形式で結果を返してもらう内容にする
- 記録画面の貼り付け欄にClaudeの返答を貼ると、`[IELTS-RESULT]` ブロックを読み取って各欄に自動入力する。足りない項目は手で入力する

```
[IELTS-RESULT]
skill: Reading
difficulty: 6.5
correct: 32
total: 40
comment: 段落の言い換えに時間がかかった
```

Writingの場合:

```
[IELTS-RESULT]
skill: Writing
task: 2
overall: 6.5
task_response: 6.0
coherence_cohesion: 6.5
lexical_resource: 6.5
grammar: 7.0
feedback: |
  （フィードバック本文）
```

- 指示文のテンプレートは設定画面から編集できるようにする

#### Speaking

既存の「IELTS Speaking 練習ツール」（ローカルで動くFastAPIアプリ、`http://localhost:8000`）を使う。**このツール側には手を入れない。**

- PCのみ: Speakingタブにツールを埋め込む（iframe、マイクの使用を許可する設定を付ける）
- ブラウザの制限で埋め込みが動かない場合や、ツールが起動していないときは「ツールが起動していません」と表示し、「別タブで開く」ボタンを出す
- スマホでは埋め込みを出さず、記録と推移だけ表示
- 結果の取り込み: ツールが保存する `data/sessions/〇〇.json` をドラッグ＆ドロップ（複数可）で取り込む
  - 取り込む項目: 日時、Part、質問、目安バンド（Fluency & Coherence / Lexical Resource / Grammatical Range & Accuracy）、WPM、フィラー回数、1秒以上の沈黙の回数
  - 同じファイルは二重に取り込まない（ファイル名で判定）
- Pronunciationはツールでは評価しないので空欄。italkiなどの結果を手入力で追加できる
- Speakingのバンド目安は、入力されている観点の平均

#### 推移

- 技能ごとのバンドスコアの折れ線グラフ。目標バンドのラインを表示（目標は設定で変更可）
- 4技能の直近スコアの平均からオーバーオールの目安を計算する。端数はIELTSの規則に従う（.25は.5に、.75は次の整数に切り上げ）
- SpeakingのWPM・フィラー回数・沈黙回数の推移グラフ

## 6. データ設計（テーブル案）

すべてのテーブルに `id`（uuid）、`user_id`、`created_at`、`updated_at` を持たせる。以下は主要な列のみの案で、実装時に調整してよい。

**タスク**
- `task_categories`: name, color
- `tasks`: title, body, category_id, due_date, status, completed_at, link_target, recurrence_id
- `subtasks`: task_id, title, done, sort_order
- `task_logs`: task_id, logged_at, body
- `task_recurrences`: rule_type（daily / weekly / monthly / interval）, weekdays, day_of_month, interval_days, active

**メモ**
- `notes`: title, body, kind（text / checklist）, color, pinned, archived, deleted_at
- `note_items`: note_id, text, checked, sort_order
- `note_tags`, `note_tag_links`

**お金**
- `money_places`: name, kind（bank / cash / emoney / credit）, initial_balance, sort_order
- `money_categories`: name, direction（expense / income）
- `transactions`: type（expense / income / transfer / adjustment）, date, amount（自分の計上額）, total_amount（まとめ払いの全額）, place_id, to_place_id, category_id, memo, is_suica_charge
- `loans`: transaction_id, person, amount, status, collected_on, collected_method, collected_transaction_id
- `card_settings`: place_id, closing_day, payment_day, payment_month_offset, debit_place_id
- `card_statements`: place_id, period_start, period_end, due_date, app_amount, actual_amount, status
- `balance_checks`: checked_on
- `balance_check_items`: balance_check_id, place_id, app_balance, actual_balance, diff

**勤怠・勉強・ドラム**
- `attendance_kinds`: name, color, special（study / drum / none）
- `attendance_records`: kind_id, started_at, ended_at, is_running, initiative_id, subject_id, material_id, page_reached, song_id, memo, source（manual / ielts）
- `initiatives`: type（exam / practice）, name, exam_date, memo
- `subjects`: initiative_id, name
- `materials`: subject_id, name, total_pages, current_page
- `plans`: subject_id, material_id, content, start_page, end_page, start_date, end_date
- `songs`: initiative_id, title, artist, memo
- `song_logs`: song_id, logged_at, body
- `band_practices`: date, place_memo
- `band_practice_songs`: band_practice_id, song_id

**謎解き**
- `nazo_ideas`: title, body, answer, explanation
- `nazo_tags`, `nazo_idea_tags`
- `nazo_performances`: title, organizer, attended_on, links（配列）, review, result, rating, format, companions
- `nazo_gimmicks`: title, memo

**IELTS**
- `ielts_records`: skill, date, source, band, minutes, notes, details（jsonb: 技能ごとの項目）, import_filename（Speaking取り込み用、一意）
- `settings`: key, value（目標バンド、換算表、Claude用指示文など）
