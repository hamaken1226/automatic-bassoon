## 5月分卒論進捗報告

〇進捗概要

　システムの大枠を作成。学習者のスピーキング音声を収集し、AIで文字起こしから評価までを行うウェブアプリケーションを開発。

ウェブドメイン：Streamlit（Python）

音声認識・分析：OpenAI API (Whisper-1, GPT-4o)

⇒キーをコード内に埋め込んでいるため、ユーザー側はAPI Key不要。

　Colabと違いいつでもアクセス可能。

音声データ保存：Google Cloud Storage（.wav形式）

テキストデータ保存：Googleスプレッドシート

（テキストデータは文字起こしデータとAIの出力したFBを含む。）

〇現在のシステム

現在は英訳問題5問と自由回答問題を5問用意し、その結果をAIが分析してCEFRのどの基準に値する英語力かをAIが判断、FBを出力する。

（将来使うシステムでも最初に同様のテストを通してユーザーのレベルを判断する）

■**ブラウザ録音＆自動文字起こし機能**

-   翻訳問題（5問）と自由回答問題（5問）の計10問を提示し、学習者がブラウザ上で直接音声を録音できるUIを実装。

-   録音後、OpenAIのWhisperモデルを用いて即座に高精度なテキスト化（文字起こし）を実行。

■**UXを考慮した「録音し直し」機能**

-   被験者のプレッシャーを軽減し、純粋なスピーキング能力を計測するため、提出前に自身の音声を確認・再録音できる確認ステップを導入。

■ **セキュアなクラウド自動連携（データパイプライン）**

-   GCPのIAM（権限）とサービスアカウントを適切に設定し、重い音声ファイルは
    Cloud Storage へ、回答テキスト・被験者ID・タイムスタンプは
    スプレッドシート へ自動で振り分けて保存する仕組みを構築。

■**GPT-4oによる総合診断フィードバック**

-   全10問の回答完了後、全テキストデータをGPT-4oに渡し、「CEFRレベルの推定」「化石化の兆候の検出」「今後の学習アドバイス」を即座に画面へ出力・保存する機能を実装。

〇今後の課題

・定期課題の実装

　本研究の肝となる、定期的に課題をこなして、その中でFBをし、ミス自体が減っていくのか。という検証のための課題を用意/実装する必要がある。

　検証期間と課題数の数も検討する必要あり。

　また、英訳なのか穴埋めなのか、自由発話なのか。どういった課題の種類を用意するかの検討も必要。

・ミスの種類の定義づけ

　ユーザーのミス分析のために、「冠詞」「時制」などの英語としてのミスの分類をこちらで指定して、その回数をユーザーごとに蓄積していくシステムを構築する必要がある。

・蓄積データの活用検証

　現在、第1テストまでしか実装できていないので、"過去のデータも参照し、FBを行う"というステップに辿りついていない。

　課題実装したうえで、わざとミスをしている発話の原稿を用意し、意図通りに指摘を行ってもらえるかの検証をし、指摘のチューニングを行う。

・化石化の定義

・どんな化石化に着目するか

・検知が正しくできているか。自分でも評価、AIとの評価差分比較。

・自分がどのくらいできるようになっているか。それがAIと同じ評価になるか。

⇒人が正しいという前提で。なんでAIが化石化と感じたか、自分が化石化と感じたか。

AIには化石化の定義を渡す。

できれば数名分はデータは取りたい。

・Whisperが正しく認識できるか。

        A〜D）のテストを実施完了**し、データを取得。

    -   実際の「生音声」と「AIの自動評価」を突き合わせ、**AI検知の限界（SLA特有のノイズ）を特定**し、本研究における「化石化」の検知定義をアップデートした。

**2. システムの概要とデータ収集の完了**

-   **測定アプローチ：必須文脈（Obligatory Contexts）の導入**

    -   「その文法ルールを適用すべきだった文の総数」に対する「実際のエラー回数」の割合（エラー率）を自動計算し、発話量に左右されない正確な定着度を測定。

-   **データセットの実施（全40問完了）：**

    -   Set A〜D（各10問、計40問）を自身で実施。

> 2問英訳問題、8問自由発話問題

-   **タスクの性質に関する検証：**
    データ全体を確認した結果、翻訳タスクよりも認知的負荷の高い「自由発話タスク」の方が、母語（L1）干渉や潜在的な癖（化石化）の検知により適していることが明確に確認できた。そのため、今後の分析評価は主に自由発話でのエラーを中心に進める。

**3. AI自動評価の二次検証（生音声との突き合わせ）と新たな発見**

取得したデータをAIに自動計算させた後、実際の録音データ（.wav）と文字起こしログを人間が突き合わせて二次検証（妥当性検証）を行った。

-   **① 音声認識（Whisper）の精度は「実用レベル」**

    -   1回答あたりの文字起こしミスは0〜2語程度、かつ文法的には軽度の誤差に留まり、分析の根幹を揺るがすような重篤な問題はなく、実用上は誤差の範囲として扱って問題ないことが確認できた。

> 発音の怪しい部分もあるので、Whisperとしての機能はむしろ高度かも。
>
> 固有名詞系統に関しての文字起こし精度は怪しい。

-   **② 重大な発見：「言い直し（Self-Repair）」による偽陽性**

    -   各セットで「構文・語順のエラー」が突出して高く出る傾向があったが、生音声を確認すると、発話中の「言い直し（つっかえや文の再構築）」が文字起こしされた際、GPT-4oがそれを「構造の破綻（エラー）」として過剰に検知しているケースが多発していた。

> 逆に検知せず文字起こしされないパターンもあった。

-   **SLA的解釈：**
    言い直しは、学習者の「自己モニター機能」が作動している証拠であり、無意識に定着してしまった強固な「化石化」とは明確に区別されるべき現象である。

**4. 本システムにおける「化石化」の再定義と検証プロセス**

「言い直し（Self-Repair）」というAIの過剰検知ノイズを踏まえ、本研究における「化石化」の定義と検知プロセスを以下の「AI×人間のハイブリッド型」に再定義する。

-   **第一段階：AIによる統計的異常値の自動スクリーニング**

システムは、以下の2条件を合成して「化石化の濃厚な候補」を自動検知する。

-   **絶対的基準：**
    単なる言い間違い（Slip）を排除するため、特定項目のエラー率が一定水準（現状の設定：20%以上）を超えていること。

-   **相対的基準：**
    本人の「全体平均エラー率」と比較して、一定の倍率（例：平均の1.3倍以上）で突出していること。

-   **第二段階：人間による手動検証と真の化石化の確定**

    -   第一段階でAIがアラートを出した項目（特に構造・語順エラー）に対し、研究者自身が実際の音声を確認する。

    -   AIが検知したミス数と、**自身で手動添削した場合のミス数を数え直し、評価が合っているか（妥当性）を確認**する。単なる「言い直し」による検知ミスを除外した上で、最終的に残った純粋な構造エラーを「化石化」と認定する。

**5. 今後のアクション**

1.  **全40問の手動添削とデータ再集計：**

    -   Set
        A〜Dの全データにおいて、AIの自動検知スコアと手動添削スコアの差異を整理し、システム評価の妥当性を検証する。

2.  **化石化閾値の最終決定：**

    -   手動添削後の正確なエラー数をもとに、AIに自動検知させるための「相対エラー数（何倍か）」と「絶対エラー数（何%か）」の最終的な閾値を検討し、システムのダッシュボードに反映させる。

## ７月分卒論進捗報告

1.  **前回の振り返り**

文字起こし精度はかなり高かった。たまに文脈にそぐわない言葉になることはあった

例）clubとcrabのような文字起こしエラー

2.  **前回の課題点の整理**

・自身の実験データの手採点

少し数字としての乖離があるように感じた。（数字が大きいという部分で）

採点AIが検知～計算までを一括で行っているため、そこでのズレが起きていると踏んだ。

3.  **今回の進捗**

・raw版とcleaned版の実装

clubとcrabのような単語の違いや、言いなおしによる文脈・文脈エラーが増えることを予防するため、文字起こし後にデータを微修正したCleaned版を実装。

文法のミスは変えず、文脈にそぐわない単語の修正や、言いなおしの削除などを搭載。

・計算方法の変更

AIに一括で計算までを行わせるのではなく、一度検知数をAIに提出させ、Pythonのプログラムとして計算する方式に変更

・他の英語学習者への実験

４名の大学生（他大学）にSet A～Dまでの実験を依頼。

4.  実験結果

・Cleaned版の精度の低さ

指定にそぐわない、文法ミスや単複のミスも修正してしまっていた。

・各学生への実験結果

3/４名の学生で化石化を検知（平均エラー+15％で化石化と判定）

ただ、極端に０％が出たり100％が出る事象が複数発生

また、謎の日本語や韓国語での文字起こしバグが発生

5.  **実験後検証**

・英語での文字起こし指定

文字起こしバグが起きたため、文字起こしのタイミングで再度言語を英語に指定し、文字起こしをもう１度行った

・raw版での再実験

Cleaned版だと自動修正が起きてエラーが消えていると感じたため、raw版の方で採点がどうなったか実験を行った。

〇結果

前回の検証に比べ、極端なスコアリングが減少した。

目視のミス量の感覚と概ね一致するものの一部謎の100％ミスが出てしまった。

また、人によって同じ問いに対する文字量に乖離があり、データとして均一でなかった。

採点を何度か行うと毎度ずれが起きることも多かった。

6.  **これからの検証**

・AIが検知している"必須文脈"の明確化

何をもって必須文脈と検知しているのか、どこをミスとしているのかを明示してもらい、どうしたら毎採点ごとのズレをなくせるか検証

・Gemini3.5との検証比較

今はGPT4oを使っているが、どちらの方が採点プロンプトに対して忠実か実験。

再現性、計算は数式で。自己評価と比較、信憑性。一度に送るリクエストが多すぎる？
